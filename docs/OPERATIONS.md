# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 晚交班后到达的取件在「晚到取件补录」提交：不晚于观察截止的补录会重算滞留率并追加 revision；截止后才取的柜件本批仍算未取，只登记不改估计。
6. 同一柜件存在两个取件时刻时，估值相同照常复核并留痕，估值不同整批暂缓（`PICKUP_AMBIGUOUS`）。
7. 补录与签发同时到达时，补录先生效即作废旧估计：工作台对旧 revision 的签发明示 `ESTIMATE_SUPERSEDED`，刷新后按新结论复核。
8. 批次页的「补录与签发结论」台账和历史列表的原因标签可查每批结论与原因；导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
